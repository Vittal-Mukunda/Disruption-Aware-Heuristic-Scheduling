# DAHS — Disruption-Aware Heuristic Scheduling

### Offline truncated-rollout labels did not recover the online teacher on one warehouse simulator

DAHS is a **selection hyper-heuristic** for dynamic warehouse order dispatching.
At every 15-minute review it chooses which simple dispatching rule to apply.
Truncated-horizon stochastic rollouts of every candidate are run *once, offline*,
over a corpus of simulated shifts; the per-rule cost vectors become a supervised
training signal for a calibrated gradient-boosted ranker.

This construction is **not new**. It is rollout classification policy iteration
and multi-pass rule selection. The paper does not claim a new mechanism. What it
offers is a comparison of *training signals* — a measured per-rule cost vector
against fitted Q-iteration and a policy gradient — on one shift corpus, with two
independent deadline clocks. PPO is not a matched simulation-step budget.

The empirical result is narrower than a distillation success story. On 50
held-out default shifts the rollout-trained selector (DAHS) has mean composite
cost **J = 382.27**, beating Always-COVERT (**455.21**; 49/50 shifts) and FIFO
(**1486.82** = **3.89×**, SFR **0.1837**). Online truncated lookahead remains
cheaper (greedy **356.98**, rolling **363.42**). Distillation is **158×** faster
(4.24 ms vs 670 ms). At a 15-minute review, 670 ms is **0.07%** of the epoch and
is unused unless a tighter review is required. A two-step label is cheaper on
the mean than the deployed four-step label. On a 12-cell robustness grid **five** methods are
frozen: the one-step teacher wins 8 cells, Always-EEDD wins 4, DAHS wins **0**.
Live evaluation uses `sim.terminal_admit: true` (mean arrived **|A| = 791**).
Production labels were generated with that flag off and were not regenerated.

This repository contains the simulator, training pipeline, baselines, trained
weights, experiment artifacts, figures, an interactive dashboard, and the
Elsevier manuscript.

# Installation

Requires **Python 3.12**. `requirements-lock.txt` pins `scipy==1.18.0`.
`pyproject.toml` requires `>=3.12,<3.13`.

```bash
python -m venv .venv
# Windows (PowerShell):
.\.venv\Scripts\Activate.ps1
# macOS / Linux:
source .venv/bin/activate

python -m pip install --upgrade pip
pip install -r requirements-lock.txt
pip install -e . --no-deps
python -c "import xgboost, sklearn, shap, stable_baselines3, omegaconf; print('ok')"
python -m pytest -q
```

## Reproducing experiments

Committed `data/`, `runs/`, and `results/` hold the current revision. Do not
run `make clean-stale`. Stage 1 must precede Stage 2. Committed `config.yaml`
carries fitted ATC/COVERT scales `3.0 / 4.0`.

| Target | Purpose |
|---|---|
| `make install` | Editable install with dev extras |
| `make gate` | Import smoke test |
| `make stage1` | Calibrate, screen, diversity, perishability diagnostic |
| `make stage2` | Label the corpus |
| `make stage2-smoke` | 3 train + 2 test shifts |
| `make stage3` | Regime layer, ranker, calibrator |
| `make stage4-teacher` | Rolling-horizon MPC |
| `make stage4-fqi` | Fitted Q |
| `make stage4-rl-sensitivity` | PPO grid |
| `make stage5-misspecification` | Label nominal, evaluate perturbed |
| `make paper-figures` | Regenerated manuscript figures |
| `make test` | pytest |

Windows without `make`: see each target's command in the `Makefile`.

**Olist.** Not in the repo. Only `experiments/a_realdata_validation.py` and
`experiments/a2_olist_arrivals.py` need
[the Kaggle dump](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)
unzipped to `Olist Dataset/` at the repo root.

## Submission gates

Both gates pass on the committed tree: 40/40 reviewer phrase anchors, and
`READY` from the build check.

```bash
python scripts/audit_reviewer_items.py
python scripts/build_submission.py --check
python scripts/build_submission.py   # needs pandoc; writes paper/submission/manuscript.tex
```

Then compile and copy the result under the manuscript number:

```bash
cd paper/submission && pdflatex manuscript.tex && pdflatex manuscript.tex
```

Pandoc resolves the citations with `--citeproc`, so the references are already
inlined — there is no bibtex/biber pass. The second run fixes cross-references.

`paper/CAOR-D-26-01812.tex` and `.pdf` are copies of `paper/submission/manuscript.{tex,pdf}`
from that build. Regenerate them; do not edit them.
